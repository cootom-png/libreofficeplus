# 布局与操作语义排查（v6.3）

2026-10-12，在 Windows、LibreOffice 26.2.5.2（构建 `cd7284b4cbbfeb507e630c1aac019f4157393acb`）中使用独立用户配置与模拟文档检查。个人文档、截图及其内容没有纳入仓库或配置包。

## 已确认的相似排版风险

模拟文档包含一个**宽 3.42 mm、高 55.16 mm、作为字符锚定**的已有文字框，框内有九个模拟汉字。所在段落设置固定行高 3 mm，下方放置 22 行表格。固定行高使框的高度没有完整占据页面，看起来只有一页。

| 操作 | 光标位于框所在段落 | 选中框所在整段 |
| --- | --- | --- |
| 标题 1、正文、默认段落样式 | 变成两页 | 变成两页 |
| 单倍行距、双倍行距 | 变成两页 | 变成两页 |
| 清除格式 | 此场景仍为一页 | 变成两页 |
| 加粗、居中 | 此场景仍为一页 | 此场景仍为一页 |

触发重排时，框数量、宽高和表格宽度没有变化；变化的是段落行距，固定行高变为比例行距，已有的高文字框把下方表格推开。已安装配置包与未安装配置包的原生实例各观察 16 个场景，结果一致。配置版行距操作读取 Ctrl+1、Ctrl+2 的有效映射后派发；这不是实际键盘输入测试。

**这是已复现且仍存在的文档结构风险，不是已修复项目。** 普通文档应用样式改变字体、段落间距及分页可能是正常行为。上述实验也不能证明用户原文档的文字框最初由“标题 1”按钮创建；原始框的产生步骤尚未确定。

遇到相似情况先撤销，保存副本后检查文字框的宽度、锚定方式、自动高度和所在段落行距。如果框本来就不需要，应在副本中把文字移回正文，再移除空框并检查表格、分页和 PDF。若框有实际用途，应按用途调整宽度、锚定及环绕，不能批量删除所有框。只想改变标题外观时，可先调整字体、字号及对齐，并重新检查分页。

本版没有拦截原生样式命令、强制保留固定行高或自动删除文档对象；这类处理可能破坏合法文本框及标题样式。

## 普通布局检查

50 项普通布局检查通过，记录见 [配置版](布局排查-配置版.json) 与 [原生对照](布局排查-原生对照.json)。范围为：

- Writer 29 项：标题 1/2、正文、默认段落、表格内和浮动文字框内样式、清除格式、对齐、缩进、行距，以及模拟 ODT/DOCX/DOC 保存重开后的对象几何与内容。
- Calc 11 项：换行、加粗、斜体、对齐、清除格式保留文字及列宽；合并居中、撤销合并；向下/向右填充的公式引用。
- Draw 10 项：固定尺寸文字框的字体与段落操作、层级，以及组合/取消组合后的文字、大小和位置。

保存重开检查比较同一文件操作前后，不能据此宣称不同格式之间完全无损。Draw 自动增长文字框、所有浮动锚定/环绕组合、真实打印、全部旧文档、格式刷跨对象复制及每个按钮的实际鼠标点击没有穷尽。本次未发现新的普通对象压窄或丢失，不表示所有文档均无风险。

## 复现与后续

`scripts/verify_layout.py` 只新建模拟文档，不读取用户文件。启动专用于测试的无界面 LibreOffice，用户配置必须位于仓库的 `.test-work/layout-audit-<唯一名称>/` 下，并使用唯一 UNO pipe；不要连接个人实例。配置版应预先把本包安装到该测试 APPDATA。使用 LibreOffice 自带 Python：

```powershell
& 'C:\Program Files\LibreOffice\program\python.exe' scripts/verify_layout.py --pipe <独立实例pipe名> --output .test-work/layout-results --configured
```

原生对照不安装配置包，并省略 `--configured`。脚本输出 PDF、模拟文件与 JSON，记录普通检查和已知风险观察；风险重现与修复分开记录。脚本关闭自己创建的文档，保留独立实例供其他验证使用。当前 CI 未安装 LibreOffice，因此只运行构建及安装相关检查，不能冒称 CI 已运行此布局实验。

下一步优先用脱敏样例补测格式刷、自动增长文字框及不同环绕方式；要定位用户原始框的创建原因，仍需在副本中复现从正常状态到出现框的完整操作顺序。
