执行顺序为“原生基线 → 配置与构建 → 隔离安装/恢复 → 原生文档操作 → 实际窗口 → 中文 PR”。本版能安全交付的改动已纳入同一 PR；上表明确列出未达到精确复刻的项目，不能将方案条目本身当成已实现功能。

后续应先逐页减少空容器和统一行高，再实现有真实功能的函数分类及弹窗内部原型。验收需同时记录参考位置、实际位置、命令行为、窄窗口结果和恢复结果，不以按钮数量作为完成率。

## v6.4 本轮交付与下一阶段

本轮完成配置层的名称纠正、粘贴选项、样式检查入口、常用操作行间距、空按钮容器收起、Draw 菜单栏简化，以及安装前模块/目录选择、字体提示、可选模板入口与可验证发布。只收起已无可用命令且不含其他原生动作控件的容器，保留原生上下文控制器。

后续执行顺序：

1. 在合成表格中验证 Calc 换行和批量输入的编辑/选区状态，再决定扩展实现；必须覆盖撤销、中文输入法与原有原生键位。
2. 验证 Writer 格式复制/粘贴的文字与段落范围；只读检查样式来源，不能默默改写已有文档样式。
3. 依次做字体、段落、单元格、页面和 Draw 属性的独立弹窗原型。字段使用 LibreOffice 的真实能力，预览、取消、撤销与恢复均须验收。
4. 逐页验证正常/窄窗口、125%/150% 缩放及对象上下文，再收敛行高、分隔线与溢出体验。当前小窗口 WPF 验收不等同于全部桌面缩放通过。

设计只借鉴功能组织与常见交互规律；保留独立名称、视觉表达、图标来源与源文件许可。不能直接复制 WPS 图形资源、完整界面皮肤、程序代码、专有素材或品牌标识；不宣称官方兼容、隶属或合作。每轮 PR 都记录已实现范围及仍有差异的操作。

发布经过 PR 检查、合并、最新 main 完整提交核对、GitHub Actions 重新构建和验收。用户在本次对话明确批准实施、提交 PR 和发布，作为本次发布的批准渠道；仓库未配置 GitHub 环境审批时，不声称存在该保护。工作流临时包保留 7 天，既有版本与用户首次备份保留供回退。
